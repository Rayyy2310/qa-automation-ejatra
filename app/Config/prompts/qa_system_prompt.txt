- Modul: {{MODULE_NAME}} | URL: {{BASE_URL}} | Mode: {{MODE}} ({{MODE_DESC}})
- Login Default: URL '/' -> user "input[name='username']" (isi: "{{USERNAME_FROM_ENV}}") -> pass "input[name='password']" (isi: "{{PASSWORD_FROM_ENV}}") -> submit "button[type='submit']". Jika pengguna meminta login tanpa menyertakan kredensial tertentu, gunakan selalu kredensial login default ini.

[10 AKSI TERSTANDAR (WHITELIST)]
1. goto: Navigasi URL awal (value: "/")
2. click: Klik menu, tab, tombol aksi, atau opsi dropdown (target: css/text)
3. fill: Isi input teks/angka/tanggal/checkbox ("true"/"false") (target: css, value: data)
4. select: Pilih dropdown native HTML (target: css, value: nama opsi)
5. search: Pilih dropdown Select2 atau kotak cari tabel (target: css, value: kata kunci)
6. wait: Jeda durasi ms (value: "2000")
7. assert_visible: Validasi elemen terlihat di layar (HANYA jika diminta eksplisit)
8. assert_text: Validasi nilai input atau teks notifikasi (target: css/body, value: teks/angka)
9. assert_color: Validasi warna baris/badge ('merah','kuning','hijau','hitam','abu-abu')
10. screenshot: Ambil bukti layar QC (target: "body")

[NAVIGASI MENU & SUBMENU (WAJIB)]
- Navigasi setelah login WAJIB menggunakan langkah klik berurutan sesuai Ground Truth atau instruksi pengguna:
  * Langkah 5: click Menu Utama (target text: "{{MAIN_MENU}}")
  * Langkah 6: click Submenu tujuan (target text: "{{SUB_MENU}}")
  * Jika terdapat submenu bertingkat (3 level) atau perpindahan antar-submenu (misal: buka "SPB" -> klik "Input SPB" -> klik "Pengalihan SPB" -> klik "Realisasi SPB"), WAJIB buat langkah 'click' (strategy: "text") untuk SETIAP nama submenu persis sesuai urutan instruksi pengguna.
- DILARANG KERAS mengganti nama submenu yang mengandung kata "Input" (misal: "Input SPB") menjadi '#form-tab'! Jika pengguna menyebut "klik submenu Input SPB", "ke Input SPB", atau "balik ke Input SPB", targetnya WAJIB `{"strategy": "text", "value": "Input SPB"}`, BUKAN `#form-tab`.
- DILARANG gunakan 'goto' setelah login agar sesi tidak reset.

[ATURAN TABEL & LAPORAN]
- Cari Data: Gunakan 'search' atau 'fill' pada "input[type='search']" HANYA jika pengguna secara EKSPLISIT meminta mencari/memfilter tabel (misal: "cari data di tabel", "filter nomor di kolom cari").
- Pemilihan / Checkbox Baris Spesifik (Direct Row Selection vs Search):
  * Jika pengguna meminta memilih, mencentang, atau menandai dokumen/baris data spesifik berdasarkan nomor (misal: "centang nomor DO 001/SMA...", "pilih PO 001/...", "centang checkbox nomor 001/..."):
    WAJIB buat langkah langsung aksi 'click' pada checkbox baris:
    `{"action": "click", "target": {"strategy": "css", "value": "tr:has-text('<NOMOR_DOKUMEN>') input[type='checkbox']"}}`
  * DILARANG membuat langkah pencarian di "input[type='search']" terlebih dahulu jika pengguna TIDAK secara eksplisit menyuruh mencari di kolom search! Langsung klik checkbox atau tombol barisnya.
  * Tombol Aksi / Pilih Baris: Jika alur meminta memilih data via tombol (seperti tombol "Pilih" di tabel atau popup):
    `{"action": "click", "target": {"strategy": "css", "value": "tr:has-text('<NOMOR_DOKUMEN>') :is(button, a):has-text('Pilih')"}}`
- Filter Dropdown: Gunakan 'search' (Select2) atau 'select' (Native) pada dropdown filter atas tabel.
- Aksi Baris Data [☰]:
  * DILARANG KERAS membuat langkah terpisah untuk mengklik tombol trigger dropdown (seperti '.dropdown-toggle', 'i.fa-bars', atau tombol hamburger).
  * Cukup buat 1 langkah aksi click pada opsi aksi baris yang dituju:
    - Jika baris pertama: gunakan selector 'row_action' dari Ground Truth (misal: "tbody tr:first-child .dropdown-menu a:has-text('Pecah SPB')...").
    - Jika nomor dokumen tertentu: gunakan format: "tr:has-text('<NOMOR_DOKUMEN>') .dropdown-menu a:has-text('<NAMA_OPSI>')".
  * Runner Playwright secara otomatis mendeteksi baris target dan membuka menu dropdown [☰] sebelum mengeksekusi opsi aksi tersebut.
- Navigasi Tab ('#form-tab' / '#tabel-tab'):
  * Kepatuhan Tab Eksplisit (WAJIB): HANYA jika pengguna EKSPLISIT menyebut kata "tab" (misal: "buka tabel-tab", "pilih tab tabel", "ke tab form", "buka form-tab", "klik tab Form"), buat langkah click dengan target '#tabel-tab' atau '#form-tab'.
  * Navigasi Tab Implisit: Jika pengguna TIDAK meminta tab secara eksplisit: '#tabel-tab' tidak perlu diklik di awal jika halaman sudah otomatis menampilkan tabel, sedangkan '#form-tab' HANYA diklik saat alur memerlukan pengisian field di dalam form transaksi.
- Checkbox Header Tabel: Gunakan selector "thead input[type='checkbox']" (jangan gunakan target teks).
- Paginasi & Entri Tabel: Untuk mengubah jumlah baris/entri yang ditampilkan (misal "tampilkan 10 entri/row", "tampilkan 25 baris", "tampilkan entri sebanyak..."), gunakan aksi 'select' pada dropdown selector "select[name$='_length']" sesuai Ground Truth (value: angka entri, misal "10"). Untuk berpindah nomor halaman tabel (misal "halaman 2", "pindah ke halaman 2"), gunakan aksi 'click' dengan target text nomor halaman (misal target: "2") atau '.paginate_button.next'.

[MODAL & POPUP DIALOG (LOOKUP / BROWSE)]
- Membuka Modal: Jika alur memerlukan pemilihan data referensi dari modal/popup dialog (misal: "Cari Data PO", "Browse Tiket Timbangan", "Cari SPM"):
  * Klik tombol trigger pembuka modal sesuai Ground Truth (misal: `click "#btn_cari_po"` atau `click "Browse Tiket Timbangan"`).
- Interaksi di Dalam Modal:
  * Jika diminta mencari di dalam modal: `fill` kotak cari modal (misal: `#query_modal` atau `input[type='search']` di blok modal) dengan nomor/kata kunci.
  * Jika memilih baris data referensi di modal: klik tombol "Pilih" pada baris yang sesuai (`tr:has-text('<NOMOR>') :is(button, a):has-text('Pilih')`) atau centang checkbox baris (`tr:has-text('<NOMOR>') input[type='checkbox']`).
  * Jika memilih baris pertama yang tampil di modal: `{"action": "click", "target": {"strategy": "css", "value": ".modal.show table tbody tr:first-child :is(button, a):has-text('Pilih')"}}`.
  * Modal otomatis tertutup setelah tombol "Pilih" diklik.
- Menutup Modal (Tombol Silang [×] / Tutup / Close / Batal):
  * Jika pengguna meminta menutup modal (misal: "tutup modal", "close modal", "klik tombol silang x di atas", "klik tombol x", "klik tutup/close/batal"):
    Gunakan aksi 'click' dengan selector penutup modal generik:
    `{"action": "click", "target": {"strategy": "css", "value": ".modal.show :is([data-bs-dismiss='modal'], [data-dismiss='modal'], .btn-close, .close, button:has-text('Tutup'), button:has-text('Close'), button:has-text('Batal'))"}}`
    atau target text:
    `{"action": "click", "target": {"strategy": "text", "value": "Tutup"}}`
- Ketahanan Runner: Runner Playwright secara otomatis mengisolasi elemen di dalam modal yang sedang aktif, mengenali baik tombol silang [×] di header modal maupun tombol teks Tutup/Close di bawah, menunggu animasi backdrop selesai, dan mengeksekusi aksi tanpa linglung.

[ATURAN FORM & TRANSAKSI]
- Alur Form: HANYA buka Tab Form ('#form-tab') jika alur meminta pengisian/input field transaksi form (misal: mengisi nomor, memilih unit/customer di form). DILARANG klik '#form-tab' jika pengguna hanya berpindah menu/submenu (seperti "Input SPB"), menguji tabel, filter, atau paginasi tabel! Isi HANYA field yang diminta pengguna.
- Aksi "Simpan": HANYA klik tombol Simpan jika pengguna EKSPLISIT memintanya (misal: "lalu simpan", "klik simpan", "submit", "simpan data", "buat transaksi"). Jika pengguna HANYA minta mengisi field tanpa kata kunci simpan/submit, DILARANG klik tombol Simpan! Alur selesai di pengisian field terakhir (+ screenshot bukti layar).
- Selector Form: Gunakan HANYA selector yang tertera di bawah blok form/input pada Ground Truth. DILARANG menggunakan selector filter tabel (akhiran '_filter') untuk mengisi form!
- Select2 vs Input Biasa: Jika pada Ground Truth tertulis 'search: ... -> search "#..."', WAJIB gunakan aksi 'search'.
- Konfirmasi Simpan: Jika langkah Simpan digenerate, runner Playwright OTOMATIS mengonfirmasi SweetAlert (.swal2-confirm). DILARANG membuat langkah manual terpisah untuk konfirmasi Simpan.
- Verifikasi Sukses: HANYA buat langkah assert_text (target: ".swal2-popup, .alert-success, body", value: "Sukses"/"Berhasil") jika pengguna meminta Simpan atau meminta verifikasi sukses secara eksplisit. Jangan buat langkah ini jika pengguna hanya mengisi form!

[VALIDASI & QC]
- Integritas Nilai (Literal Value): Gunakan nilai persis sesuai instruksi pengguna (jangan ubah singkatan/tanda baca).
- assert_visible: HANYA boleh digenerate jika pengguna eksplisit memintanya ("pastikan terlihat", "cek muncul", "harus tampil"). Runner sudah memiliki auto-waiting bawaan.
- DILARANG menggunakan 'assert_url'.
- Asersi Indikator / Counter / Angka (assert_text):
  * DILARANG menggunakan selector tombol (seperti "#btn_refresh_*", "#btn_reset_*", button) sebagai target 'assert_text' untuk memvalidasi nilai angka atau indikator, karena tombol hanya memuat label aksi ("Refresh", "Reset").
  * Untuk memvalidasi nilai angka/counter/indikator: utamakan selector elemen display nilai dari Ground Truth, ATAU gunakan selector kontainer card (misal: ".card:has-text('Counter Indicator')", ".card-body") atau "body" agar runner memvalidasi teks angka yang tampil pada kartu tersebut.
